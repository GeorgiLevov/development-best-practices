# Pair guided study with unguided passion projects and intentional experiments to escape tutorial hell

**When to use**: When consolidating a new framework, planning your next learning project, or feeling stuck cycling through tutorials.

**Rule**: Alternate deliberately between **guided learning** (courses, docs, tutorials—so you don't reinvent every wheel) and **unguided practice** (building real projects from scratch, completing stretch goals, and looking up docs on your own). Because software mistakes are free, treat tutorials like a lab: modify code, form hypotheses about what breaks if a line changes, and verify. When graduating from a curriculum, build a project tied to a real personal interest or need (mixing in 1–2 stretch tools like TypeScript, unit tests, or auth—not ten at once), and leverage cross-domain skills since concepts across tools compound.

**Example**:
```text
Learning loop:
1. Guided lesson -> experiment by breaking/modifying 1 assumption
2. Unguided stretch goal -> read docs, hit real bugs, resolve without walkthroughs
3. Passion project -> ship something personally useful + add 1-2 new tools
```

**Avoid**: Going straight from tutorial to tutorial without unguided building ("tutorial hell"), copy-pasting examples verbatim without testing variations, or adding too many unfamiliar tools to one project and burning out.

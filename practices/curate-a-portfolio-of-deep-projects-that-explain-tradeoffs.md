# Curate 2–5 deep projects on a dedicated portfolio site that highlights engineering decisions

**When to use**: When building or refreshing a developer portfolio, project showcase, or GitHub pinned repos.

**Rule**: Curate 2–5 substantial, non-trivial projects rather than listing every tutorial clone or small exercise. Build a clean, distraction-free portfolio site (not just raw GitHub repo links) that guides reviewers through each project: state the problem, link a working live demo without login walls, and explicitly explain *what was technically hard*, *how you solved it*, and *what tradeoffs you weighed*—things obvious to you as the author are invisible to skimming hiring managers. Contributing well-scoped open-source fixes or building small tools around companies' public APIs also provides strong signal.

**Example**:
```markdown
## Project Case Study Checklist
- Live demo (works immediately, zero login required) + source link
- Problem statement & target user
- 2-3 specific technical challenges (e.g., race-condition cancellation, SSR FOUC prevention)
- Tradeoffs & what you would improve next
```

**Avoid**: Featuring generic to-do/calculator tutorial clones at the top of a portfolio, linking only to bare GitHub repos with default `create-next-app` READMEs, or hiding real projects behind broken demos.
